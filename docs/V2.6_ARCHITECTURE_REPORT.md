# V2.6 architecture preparation — implementation and validation

Date: 2026-09-07. Builds still identify the source as V2.5.4; no V2.6 release artifact is claimed.

## Completed follow-up sequence

1. **Undo/redo reliability:** stage the live inverse snapshot, prepare the target engine, retain the previous engine during UI installation, and commit history only on success. Failures preserve document and history; history jumps stop at the first failed step.
2. **Annotation transactions:** creation/removal, geometry, text, properties and JSON import now use one successful-action undo boundary. Unsupported JSON records remain skippable; actual strict-mode application failures roll back the batch.
3. **Watermark/redaction transactions:** multi-page text/image watermarks and redaction application restore the entire pre-action PDF after a propagated failure. Existing confirmations remain.
4. **Gradual viewer extraction:** `ui/mutation_controller.py` now coordinates mutation/history lifecycle. The viewer keeps its existing tool entry points, rendering widgets and view-state helpers; those delegate to the controller. This is a bounded extraction, not a full viewer rewrite.
5. **Shared atomic output:** `core/io_atomic.py` stages files in the target directory, commits only when the scope completes successfully, and cleans staging files on failure. PDF save, page extraction, annotation JSON/summary exports and flattened PDF copies now use it. PDF validation stays before replacement. The helper does not promise power-loss durability or atomicity across multiple output files.

New regression cases verify inverse-snapshot storage failures; missing/corrupt/unreadable history; UI installation failure; retry after recovery; single-entry annotation actions; partial multi-page mutations; skipped-only imports; staged-output writing/validation/replacement failure; destination preservation and temporary-file cleanup. Existing engine save-validation and encryption tests remain in the suite.

## Remaining release work and limits

These are source-level changes validated locally on Windows/Python 3.12.14. Remote Linux/macOS CI, native installer build/signing, clean-machine checks and real printer validation were not executed. No release was published.

Snapshots remain synchronous and memory-backed; history remains temporary and session-local. The legacy standalone stack and headless import APIs retain their existing defaults. Other file-producing modules can migrate to atomic_output incrementally; this change does not claim all application IO now uses one helper. Further viewer extraction should follow concrete maintenance needs and existing regression coverage.
